# Deep E2E audit — 2026-10-03

Status: COMPLETE. Provider v0.2.4 and Pi OpenCodeReview v0.1.1 are released, installed and verified in fresh Pi processes.

The audit uses real Pi RPC and the public Pi SDK against the already-running codex-chatgpt-web 6.1.4 bridge. Local HTTP fault fixtures exercise the actual Pi retry policy and tool pipeline without sending faults to ChatGPT. Live tests create isolated sessions and toy workspaces. Company repositories and existing shared sessions are outside the test scope.

## Findings and fixes

1. **Ambiguous failures could replay a submitted browser request.** On v0.2.3, generic HTTP 502/504, connection loss before headers, and 429 each produced four HTTP requests and three Pi retries, even when the bridge error included retryable=false. The provider now suppresses automatic replay of retry-classified ambiguous outcomes. Explicit connection-refused, authentication/input errors and cancellation retain their semantics. Original diagnostics remain available through /chatgpt-web-status.
2. **Sol branch summaries defaulted to unsupported effort none.** The public Pi branch summarizer omits reasoning. Sol rejected the actual request with HTTP 400. Control summaries now inherit the session thinking level, with Medium as the fallback. Explicitly supplied reasoning and ordinary requests remain unchanged.
3. **Abort recovery lost instruction lineage.** Responses omits user item IDs. The adapter previously assigned an ID only to the latest instruction, so that ID disappeared when the instruction became history. A subsequent turn could fail with “A newer Codex instruction superseded this ChatGPT response.” The adapter now supplies stable IDs from user timestamp and canonical content and preserves explicit incoming IDs. A live abort test prevented the command's late write and recovered within the same session. Caller cancellation also takes precedence over a transport error.

4. **Fresh review could not prove base-side instruction absence.** A real Sol Medium successor review correctly blocked with POLICY_COVERAGE_INCOMPLETE after AGENTS.md context returned CONTEXT_NOT_CAPTURED. Pi OpenCodeReview 0.1.1 adds code_review_context view=base from immutable workspace HEAD, range merge-base or commit parent. A successful tree lookup with no entry yields a digest-bound exact-path absence receipt. Git errors, symlinks and invalid paths stay errors. Initial commits use explicit empty-tree evidence. The review guard still permits only review tools; policy assessment requirements remain enforced. The prompt now explains receipt scope, admitted assessment states and revision recovery.

## Test interpretation

Early harness failures are retained in the audit history rather than counted as product defects:

- A compaction assertion looked only in the summary, although Pi retained the second marker in recent context.
- The abort RPC response arrived after agent_settled; waiting only after the response lost the idle event.
- An underscore in a concurrent marker was escaped in Markdown; the controlled isolation test now uses alphanumeric markers.
- A browser fixture requested preserve-user-attention and then tried to close its tab. The live companion refused close with ATTENTION_POLICY_REFUSED/preserve_forbids_close. The cleanup fixture now opens inactive tabs without that incompatible policy.
- A 64×32 color image returned BLUE BLUE rather than RED BLUE. The independently validated 512×256 fixture passed. The small-image misclassification remains an observed model accuracy limit; it is not erased by the larger fixture result.

An original repaired review fixture finalized with a LOW null-input finding under the mandatory generic null-check rule. The new fixture handles null/undefined explicitly so the assignment defect is isolated. A later source run reported an upstream safety block before Pi executed any review tool; that run is not counted as acceptance.

## Runtime boundary and browser authorization

Workbench and the bridge changed runtime during the audit; the previous /tmp records disappeared. The assistant did not issue a shared-runtime restart. Subsequent raw logs are retained in the repository's ignored .tmp directory, and sanitized results will be committed under docs/evidence.

After the runtime boundary the companion returned BROWSER_AUTHORIZATION_REQUIRED/current_host_session_not_granted. That attempt made no click request and owned no tabs. The user subsequently granted the new session; the fresh positive Firefox acceptance passed with exactly one fixture POST and zero owned tabs after both normal and fallback cleanup.

An earlier preserve-user-attention fixture opened an inactive test tab before the runtime boundary and close was refused. No claim is made that all earlier browser tabs have been removed.

## Reproduction

Use a new output directory for every run. The live commands consume real ChatGPT requests and use the provider package installed in Pi by default:

- python3 scripts/stress-e2e.py --output .tmp/stress-unique
- python3 scripts/fault-e2e.py --output .tmp/fault-unique
- python3 scripts/authority-e2e.py --output .tmp/authority-unique
- node scripts/branch-e2e.mjs .tmp/branch-unique
- node scripts/browser-e2e.mjs .tmp/browser-unique
- node scripts/review-e2e.mjs .tmp/review-unique /absolute/path/to/pi-open-code-review/scripts/live-review.mjs
- python3 scripts/live-acceptance.py auto --output .tmp/auto-unique

The review wrapper uses the installed extension by default and adds explicit project authority to its disposable baseline; it does not change installed runtime files.

The browser command needs an already-authorized Firefox session and exercises only its own localhost fixture. The review command creates a fresh toy Git repository, reviews an intentional assignment-versus-comparison bug, then reviews the repaired successor. It does not reuse the review package's existing fixture.
